# Bunaa Studio V28 — تقرير المراجعة والاختبار

## نطاق العمل

- نقطة البداية: نسخة Bunaa Studio V27 المحفوظة محليًا في المحادثة.
- لم يتم تعديل أو رفع أي ملف إلى GitHub، ولا يحتاج تشغيل الناتج إلى GitHub.
- تم الإبقاء على ملفات المصدر القديمة وتقارير V27؛ أُضيفت التحسينات والاختبارات ووثائق التشغيل دون إسقاط أوامر المحرر السابقة.

## الإصلاحات والإضافات

1. **شريط علوي أبسط بلا تمرير أفقي:** تقليل كثافة عناصر الشريط، وضم الأوامر الأقل استخدامًا إلى قائمة «المزيد». بقيت معرّفات الأوامر الأصلية ووظائفها، وأُعيد ترتيبها بدل حذفها. الشريط يلتف في الشاشات الضيقة بدل فرض سكرول أفقي.
2. **الحجم الطبيعي للعناصر:** العناصر القصيرة، مثل الزر والرابط والعنوان، لا تتمدد تلقائيًا لتملأ عرض مساحة العمل. العناصر الهيكلية الكبيرة تحتفظ بعرضها المناسب.
3. **التعامل المباشر بالماوس:** سحب العنصر لتغيير موضعه؛ مقابض للحافة لتغيير العرض أو الارتفاع، ومقبض للزاوية لتغيير الاثنين. الحركة والحجم مقيدان بحدود مساحة الرسم حتى لا تختفي المقابض خلف حدود القص.
4. **توافق الأجهزة والتاريخ:** الموضع والحجم يُحفظان وفق الجهاز (سطح المكتب/الجهاز اللوحي/الهاتف)؛ واختُبر التراجع والإعادة بعد تغيير الحجم.
5. **عزل أدوات التحرير:** مقابض تغيير الحجم تخص المحرر ولا تنتقل إلى HTML المعاينة أو ملفات الموقع المُصدّرة.
6. **بناء مستقل:** أضيف `build_bundle.py` لإعادة دمج وحدات المصدر داخل ملفي HTML باستخدام Python القياسي فقط؛ لا يتطلب تنزيل حزم أو اتصالًا بالشبكة.

## الاختبارات المنفذة فعليًا

### سلامة الملفات والكود

- `python build_bundle.py`: نجح وبنى 49 وحدة JavaScript متزامنة مع `index.html` و`Bunaa.html`.
- `python tests/verify_project.py`: نجح؛ **10 مجموعات تحقق**.
- `node --check bundle-extracted.js`: نجح.
- وُجدت 49 وحدة مصدر و135 مرجع استيراد ثابتًا، ولم يُعثر على مراجع وحدات غير موجودة.
- كل من ملفَي HTML يحتوي 280 عنصر HTML ساكنًا و96 معرّفًا بلا تكرار.
- `index.html` و`Bunaa.html` متطابقان، واحتُفظت معرّفات 21 أمرًا قديمًا، مع التحقق من وجود جميع الأوامر التسعة المنقولة داخل قائمة «المزيد».

### اختبار Chromium من الواجهة إلى التصدير

شُغّل اختبار Playwright فعليًا، وأنشأ مشروعًا من واجهة التطبيق ثم تحقّق من:

- بدء التطبيق وإنشاء مشروع دون أخطاء JavaScript.
- بقاء الزر بعرض طبيعي أصغر من نصف عرض مساحة العمل، بدل التمدد بعرضها.
- سحب عنصر بالماوس وحفظ الإزاحة الأفقية والرأسية.
- تغيير عرض العنصر وارتفاعه من مقبض الزاوية وحفظ القيم، ثم اختبار التراجع والإعادة.
- اختبار تغيير العرض وحده من المقبض الجانبي، والارتفاع وحده من المقبض السفلي، والسحب للداخل لتصغير البعدين؛ لم يتغير البعد غير المستهدف في اختبار كل حافة.
- حفظ موضع مستقل للجهاز اللوحي دون تغيير موضع سطح المكتب.
- فتح المعاينة والتأكد من عدم ظهور مقابض المحرر فيها.
- فتح قائمة «المزيد» وإغلاقها بمفتاح Escape أو بعد اختيار أمر، مع فتح أداة تدقيق الجودة.
- تنزيل ZIP الموقع المُصدّر من التطبيق نفسه؛ اجتاز فحص CRC واحتوى الملفات الأساسية، بما فيها `index.html` و`styles.css` و`script.js` و`project.json` و`404.html` وملفات بيانات الموقع.
- عدم وجود أخطاء صفحة أو أخطاء Console أثناء الاختبار (`pageErrors=[]`, `consoleErrors=[]`).

### الانحدار المتجاوب

جرى تغيير عرض Chromium إلى الأحجام التالية أثناء تشغيل المحرر، وفُحص كل من شريط الأدوات والصفحة كلها. لم يظهر تمرير أفقي للشريط أو للصفحة:

| عرض نافذة المتصفح | ارتفاع الشريط العلوي | تمرير أفقي |
|---:|---:|---|
| 1440px | 54px | لا |
| 1180px | 54px | لا |
| 900px | 88px | لا |
| 560px | 123px | لا |
| 390px | 123px | لا |
| 320px | 158px | لا |

واجتاز اختبار مساحة المحرر المستقل حالات اللوحات المفتوحة، وإغلاق اللوحة اليسرى، وإغلاق اللوحتين، ثم إعادة فتح اللوحة؛ ظل عرض Canvas موجبًا في كل حالة.

## التشغيل والتبعيات

- الاستخدام العادي: فك ZIP ثم فتح `OPEN_FIRST.html` أو `index.html` في متصفح حديث؛ لا يلزم Python ولا Node.js ولا خادم ولا اتصال بـGitHub.
- `build_bundle.py` اختياري لصيانة الكود بعد تعديل ملفات المصدر.
- اختبار Chromium اختياري للصيانة فقط، ويحتاج بيئة اختبار فيها Python وPlaywright وChromium.

## حدود التحقق

اختبارات التفاعل الآلي أُجريت في Chromium واحد؛ لم تُنفّذ اختبارات متصفح منفصلة في Firefox أو Safari. اختُبر التطبيق الفعلي بتحميل محتوى ملف HTML نفسه داخل Chromium. محاولة فتح المسار مباشرةً بصيغة `file://` حُجبت بواسطة سياسة المتصفح في بيئة الاختبار (`ERR_BLOCKED_BY_ADMINISTRATOR`)، لذلك لا أسجّل فتح المسار المباشر كاختبار ناجح هنا. لا يتطلب التشغيل على جهاز المستخدم GitHub أو اتصالًا بالخادم؛ لكن اختلاف إعدادات المتصفحات المحلية لا يمكن إثباته من هذه البيئة. وظائف الحسابات والخدمات الخارجية التي قد تتطلب حسابات أو مفاتيح حقيقية لم تُعتبر ناجحة لمجرد اجتياز اختبارات الواجهة. الاختبارات هنا تثبت الوظائف المذكورة فقط ولا تدّعي تغطية كل حالة ممكنة.
